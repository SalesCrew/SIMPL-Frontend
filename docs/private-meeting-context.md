# Private meeting context

This extends the existing owner-only analytics route and lazy entry chunk. It uses existing SIMPL typography, label colours, Radix tooltip/popover/dialog patterns and responsive styles. No meeting source data is bundled.

The six primary filters use actual existing label IDs: SPARK/Coke, ROVER/Mars, Compass/Samsung, OBI, Nespresso and SIMPL. GM/SM stay supplementary Coke tags. Cards without these labels remain in unfiltered totals. The old internal `state.project` key is retained for report-state compatibility but stores a label ID, never a column/project name. Project columns remain original task metadata only.

`meetings/chart-bridge.js` supplies stable chart controls and an overlay positioned over the actual SVG. The chart renderer records existing scales and per-series coordinates in a WeakMap; meeting points use only a real value on the selected line. Events never enter metric series, scales, correlation calculations or moving averages. Missing/undated/warm-up dates remain in the top overview, without a separate strip below each chart. Categorical plots only receive markers when an actual moving-average time-series is displayed. Unknown dates are listed without an invented point. Meetings sharing a day/KW or overlapping at available pixel width retain every identity in a grouped picker.

The catalogue is compact and paginated. Details and each selected-label Markdown protocol load separately on demand, through verified-session owner APIs. Markdown skips raw HTML; custom renderers suppress unsafe/local links and remote images, and resolve available source notes by meeting identity. No original Markdown is parsed to infer presentation or chronology in the browser.

Opening a dialog suspends meeting tooltips/group popovers. Browser-history navigation and breadcrumbs preserve the underlying task filters, interval, overlays, moving-average tick settings and scroll. Changing accounts unmounts private portals and aborts requests. JF is a separate category and never receives inferred project labels. Combining JF with a specific label shows a clear empty state while task metrics remain selected.

## Custom overlay thresholds

The compact threshold popover uses existing Radix and SIMPL controls: select the Y axis, enter a finite reference value, optionally choose curves/background, then Apply. A draft never recolours the chart. Green means at/above the chosen reference and red below; it is a user-defined visual comparison, not a new productivity score. Lines are fully opaque and backgrounds use opacity below 0.1. Distinct stroke patterns and matching legends retain multiple-curve identity, including moving averages. Original SVG paths, numeric axes, CSVs and correlation calculations remain unchanged.

Each axis/unit has its own rule. Native and normalized scales preserve separate background choices; an incompatible unit never inherits a numeric cutoff. Only one axis supplies the background at a time to avoid contradictory overlapping fills. SVG clip paths colour the original geometry exactly, including crossings and manual clipping; zero/negative/out-of-range cutoffs are supported. Rules survive the existing in-memory owner refresh/view restoration, alongside overlay and average settings. No shared storage or public data is introduced.

Implementation: `overlay-thresholds.js`, `ThresholdControl.tsx`, `thresholds.css`. ## Gelesen → Fertig and computed reference lines

The overlay adds a daily acknowledgement-to-finish mean and a rolling 28-complete-day mean, both in calendar hours/task. Daily values include only tasks completed on that Vienna day with an eligible own native SIMPL review stamp. The 28-day value pools elapsed hours and task counts; it never averages daily averages or assigns zero duration to empty days. Weekly daily-means pool their numerators/denominators, while the rolling line keeps its last observed day value. Missing windows stay gaps; the first full native window ends 28 September 2026. Imported review stamps and unsupported timestamps affect only these two metrics; all other historical task counts remain unchanged.

`read-cycle.js` supplies audited numerators, sample coverage, exclusions, explanations and CSV fields. The API's native boundary is verified against the actual private import ledger; read state is not inferred from label names or card IDs. The latest retained read/finish stamps measure delivery delay with waiting, not effort or difficulty. Read/unread toggles can replace the stored start. Label, period, comparison-start and special-card filters apply normally. The quick selection “Menge & Durchlaufzeit” pairs completion throughput with the 28-day duration; it does not infer that longer calendar duration proves more work.

In “Schwellenwerte”, choose “Durchschnitt einer Datenreihe”, a currently displayed series and the latest 28 full calendar days or selected visible period. The resulting horizontal reference provides the existing green/red split. Cycle references pool actual task durations/counts; ordinary series references average available complete interval values (including real zero values, excluding missing/partial values). Moving-average references use their existing original-unit values and their parent series' normalization domain. The original value, sample count, dates and method are visible. Applying is explicit, then active computed rules update with data/filters. An absent source disables its rule instead of reusing a stale numeric value. Native side/unit and normalized rules remain separate; axis limits, original paths and data CSV values are unchanged by coloring. Common-date boundaries are honored for visible-period references.

Implementation: `read-cycle.js`, `scripts/read-cycle-analytics-adapter.mjs`, threshold controls/runtime and the existing generator. Original local JSON snapshots and standalone report files are unchanged; only reviewed app code/static markup is generated. New task/daily/overlay CSV fields retain read stamps, exclusion reasons, eligible counts and summed hours. Private live-data fixtures use timestamps and redacted titles outside Git.
